# 小說／劇本／大綱 → AI 分鏡表

把文字故事拆成「每鏡一個動作、可以直接餵給 AI 生成工具」的分鏡。漫劇、短劇、動畫、真人寫實劇、MV 與廣告用的是同一套拆鏡方法，差在節奏、景別、聲音方案與資產圖的做法（見第二步與第五步的表）。

核心原則：**AI 容易亂猜的地方，在分鏡裡先替它決定好。** 生成工具沒被告知的東西（外貌、左右位置、手上拿什麼、光從哪裡來），每次都會猜得不一樣。畫面不穩、角色走樣、看起來「很 AI」，大多是從這裡來的。

**提示詞先寫完整，工具定了才套限制。** 使用者還沒選定圖像或影片工具時，提示詞照故事需要寫：動作該多快就多快、該入鏡的就入鏡、該有的字就寫，不預先為了某個工具縮短、刪細節或換拍法。工具定了，再照那個工具的能力適配（長度上限、單次秒數、語言、參考圖語法、負面詞、它做不好的動作與文字），見 `storyboard-fix` 技能的「工具定了之後」。限制每個工具都不一樣，而且幾個月就變；照某一個工具的弱點先寫，換工具時整份分鏡都得重寫。

回覆語言跟隨使用者，預設繁體中文。

## 資料分三層，各寫一次

| 層 | 內容 | 放在哪裡 |
|---|---|---|
| 設定 | 專案參數、角色、場景、道具、風格鎖定句 | `bible.json`，整個專案共用 |
| 分鏡 | 每一鏡獨有的東西：走位、動作、對白、時長 | `EPxx.json`，一集一個檔 |
| 成品 | 分鏡表、可複製的提示詞、資產提示詞、檢查結果 | 由 `scripts/build_storyboard.mjs` 組合產生 |

這樣分的原因：角色外貌必須在每一鏡的提示詞裡一字不差，手抄一定會漂移。交給腳本從設定檔組合，一致性由程式保證；使用者之後改外貌、風格或換工具，重跑一次，所有鏡頭一起更新。你只需要寫「這一鏡獨有的內容」，不要在分鏡裡重複外貌或場景描述。

欄位定義見 `references/fields.md`，完整範例見 `examples/`（`bible.json`、`EP01.json`，以及腳本產出的 `out/`）。第一次使用先讀這兩處。

輸入是大綱時，分鏡之前還有兩份：分集表（`series.json`，整季每一集演什麼）與每集的分集劇本（`EPxx-script.md`，場次、畫面與台詞），由 `outline-to-episodes` 技能做。

**同一個 plugin 的其他技能與角色。** 下面寫的 `../outline-to-episodes/`、`../storyboard-fix/` 是相對於這個技能資料夾的路徑。沒有被自動載入時，直接讀那個資料夾裡的 `SKILL.md`。

- `outline-to-episodes`：大綱 → 分集表 → 分集劇本。
- `storyboard-fix`：工具定了之後的適配、修改既有分鏡、生成結果不對時怎麼改。
- 三個審查角色（攝影與連戲、表演、美術）：拆完一集後各從一個角度挑問題，見第七步。

## 流程

### 1. 讀原文，判斷輸入是哪一種

- **小說**：把敘述轉成拍得出來的動作。心理描寫改用微表情、小動作、環境細節或旁白表現，例如「她很難過」寫成「她盯著杯子，手指停在杯緣，視線垂下」。概述、背景交代、比喻、潛台詞各有處理方式，見 `references/shot-craft.md` 第八節。
- **劇本**：場景標題直接當場景清單，對白照用不改。工作重點是把舞台指示拆成一鏡一個動作。
- **大綱或故事梗概**：內容不夠拆鏡，沒有台詞，也看不出一集該演到哪裡。照 `outline-to-episodes`（`../outline-to-episodes/SKILL.md`）先排分集表、停下來確認，再一集一集寫成分集劇本，然後把分集劇本當成劇本來拆。大綱寫了集數與單集長度的，照它的規格。
- **使用者給了單集長度**（「每集 60 到 90 秒」）：不論輸入是哪一種，都先照 `outline-to-episodes` 排分集表。小說已經有對白和動作，不用寫分集劇本，直接拿原文拆鏡。

### 2. 動手前先問參數

**讀完原文、還沒寫任何設定或分鏡之前，先用一則訊息問使用者下面這些參數，等回答了再開始。** 形式、媒材、工具、聲音一改，所有鏡頭的片段都要重寫；先問清楚，比做完再改便宜得多。

怎麼問：

- **只問還沒有答案的。** 使用者的話裡已經說了的直接採用，在訊息開頭列成「已知：豎屏漫劇、影片用可靈」。
- **每一題給選項和建議值。** 建議值從原文、題材和使用者的說法推斷，附半句理由。訊息最後說明「沒意見回覆『照建議』就好，也可以只回答想改的幾題」。
- **一則訊息問完，用不到的不問。** 題目照下表的順序；沒有旁白就不問人稱，不是短劇、漫劇或大綱就不問單集長度，不是大綱就不問付費卡點。
- **原文沒寫外貌的主要角色**，列出名字問使用者有沒有設定；沒有的話說明會先暫定，交付時列在待確認設定。配角和場景細節不在這裡問。
- **這則訊息只有問題**：不附設定表、不寫檔案。可以附一句篇幅的粗估（「這一章大約四場、六十鏡上下」），幫使用者決定單集長度。

範例：

```text
開始前先確認幾件事。已知：小說第一章、影片用可靈。
沒意見回覆「照建議」就好，也可以只回答想改的幾題。

1. 形式：漫劇／短劇／動畫／真人劇／影片。建議：短劇（對白多、衝突直接）
2. 媒材與風格：真人寫實／2D／3D／漫畫。建議：真人寫實，電影感
3. 畫幅：建議 9:16
4. 圖像工具：用哪一個？還沒定也可以，提示詞會先出不限工具的完整版
5. 聲音：旁白／後配口型／工具直接生成對白。建議：可靈能直接生成對白，用這個
6. 單集長度：這一章大約三分鐘。要切成每集 60 到 90 秒，還是一章一集？
7. 外貌：原文沒寫沈知意和許曼長什麼樣，有設定嗎？沒有的話我先暫定
```

**不問、直接開始的情況：**

- 表裡每一題都已經有答案。
- 使用者說「不用問」「你決定」「照預設」「直接開始」：用建議值開始，問題改放在第一次交付的最上面，並列出實際採用的值。
- 接續既有的專案（找得到 `bible.json` 或前一章的設定表）：參數沿用，只有新出現的事（新角色的外貌）才問。
- 修改既有分鏡、回報生成結果、換工具：照 `storyboard-fix` 做，不重問。
- 從 `outline-to-episodes` 接過來的：參數在那裡已經問過，不重問。

使用者回答後，把答案寫進 `bible.json` 的 `project`；沒回答的那幾題照建議值做，交付時再列一次。

| 要問的參數 | 建議值怎麼來 | 完全沒有線索時 |
|---|---|---|
| 形式 | 照下表的說法判斷 | 動畫 |
| 媒材與風格 | 媒材跟著形式：真人劇是真人寫實，短劇多半是真人寫實（「動漫風短劇」就不是），漫劇是漫畫或 2D 動畫，動畫是 2D 或 3D。風格依題材推斷：古裝仙俠的 2D 用國風，校園日常用日系賽璐珞，真人寫實寫攝影質感 | 跟著形式 |
| 畫幅 | 跟著形式與投放平台：漫劇、短劇 9:16；動畫、真人劇 16:9，電影感可以用 2.39:1；影片看平台 | 16:9 |
| 生成工具（圖像、影片） | 使用者指定。它決定提示詞語言、長度上限、單次秒數、參考圖語法、有沒有負面詞欄位，以及哪些動作或文字要換拍法，查 `references/tool-capabilities.md`。問的時候舉表裡兩三個工具當例子，並說明「還沒定也可以」 | **未定，不套用任何工具限制**：提示詞中英都出、圖生影片、使用首尾幀，秒數與長度上限不填 |
| 聲音方案 | 漫劇用「旁白」。短劇、動畫、真人劇以對白為主：工具有原生音訊就建議「原生音訊」，沒有或還沒定就建議「後配口型」。影片看內容：MV 是配樂，解說是旁白。漫劇但角色之間來回說話的戲很多時，同時列出「後配口型」與「原生音訊」的代價 | 同左 |
| 單集長度 | 短劇、漫劇，或輸入是大綱時才問；大綱寫了就照大綱，不問。給了長度就填 `episode_length`，並照 `outline-to-episodes` 排分集表 | 一章一集，不設上限 |
| 旁白人稱 | 有旁白才問：主角自述（第一人稱）或敘事者（第三人稱），填 `narration`，全季一致 | 跟著原文的敘事人稱；大綱沒寫就用主角自述 |
| 付費卡點 | 輸入是大綱才問：哪幾集是付費或留存卡點。不知道就先不標，不要自己挑 | 不標 |
| 主要角色的外貌 | 原文沒寫的主要角色才問 | 暫定一個具體的值，列入 `pending` |

提示詞語言跟著工具（使用者可以要求雙語），參考圖模式跟著圖像工具能不能一次掛好幾張、用編號指稱（不確定就用「文字」），這兩項不另外問。

**形式**（`format`）：

| 形式 | 使用者會這樣說 | 畫幅 | 推進方式 |
|---|---|---|---|
| 漫劇 | 漫劇、動態漫、漫畫解說、小說推文 | 9:16 | 旁白為主，畫面配合旁白；可以大量用靜幀 |
| 短劇 | 短劇、微短劇、豎屏劇、爽劇、AI 短劇 | 9:16 | 對白與衝突為主，節奏最快，每集都有鉤子和卡點 |
| 動畫 | 動畫、番、動畫短片、3D 動畫 | 16:9 | 對白與表演為主 |
| 真人劇 | 真人、寫實、實拍感、電影感、劇集、AI 電影 | 16:9 或 2.39:1 | 對白與表演為主，容許長鏡頭與停頓 |
| 影片 | MV、廣告、宣傳片、預告、片頭、Shorts | 看平台 | 跟著配樂或旁白，常常沒有完整的劇情 |

幾種常見的半明確情況：

- 只說「AI 影片」或「做成影片」：形式這一題照樣問，建議值從原文和平台推斷。
- 只說了影片工具：圖像工具這一題照樣問（它決定長度上限與參考圖張數）；圖像提示詞的語言先跟影片工具一樣。
- 工具有幾個版本而使用者沒說：照標準版填，交付時列入待確認，不必為了版本單獨問。

### 3. 建立或沿用設定檔

先找有沒有現成的設定：工作資料夾裡的 `storyboard/bible.json`，或使用者貼上來的前一章設定表。有就沿用，已有的角色與場景描述一個字都不要改，只新增（新角色、新造型、新場景）。改寫舊描述會讓前後集的角色長得不一樣。

沒有才新建，放在工作資料夾的 `storyboard/bible.json`。要點：

- **角色**分成不變的外貌（`look`：年齡、臉型、髮型髮色、眼睛、體型）和會變的造型（`variants`：服裝與狀態）。身高寫在 `stature`，只寫絕對身高（「身高約一百八十公分」），同框的人才不會畫成一樣高。插畫與動畫的頭身比（寫實七頭身、Q 版三頭身）寫在 `look`；真人寫實不用寫頭身比，寫體型就好。換裝、受傷、弄髒各開一個造型變體（C01-a、C01-b），鏡頭引用變體編號，連戲狀態才有地方記錄。
- 每個角色給一個**短稱**（`tag`，例如「黑髮及肩的年輕女子」）。影片提示詞裡用短稱指人，不用名字也不用代名詞，因為生成工具不認得名字，代名詞在多人鏡頭裡會指錯人。一群長得差不多、只會一起出現的人（「兩個蒙面黑衣人」）登記成一個角色，短稱寫成複數，並填 `group`（人數），設定圖才會畫成一群人。
- 有台詞的角色寫**聲線**（`voice`：性別年齡、音色、語速），有旁白就寫 `project.narrator_voice`。配音照它選聲音，原生音訊時腳本把它寫進每一句台詞；原文沒寫的，給一個暫定值並列入 `pending`。
- **場景**的 `space` 第一句寫這是什麼地方，包含時代與地域（「九〇年代香港唐樓的客廳」），牆面、家具、燈具和雜物的樣子大多由它決定；接著只寫不會動的東西（結構、門窗、大型家具）和它們的空間關係，例如「木桌緊靠窗邊，門在窗戶對面的牆上」。
  - 不要寫「窗在畫面左側」。畫面左右會隨機位改變，一拍反打就錯；畫面位置留給每一鏡自己寫。
  - 會移動或會變狀態的東西（桌上的碗、燈亮不亮）不要放進來，否則下一章狀態變了也改不得。它們屬於道具或每一鏡的光線。
- **反覆出現的道具**（信、鑰匙、劍）登記在 `props`，鏡頭裡寫 `{P01}`，腳本會換成同一段描述。只出現一次的小東西直接寫在鏡頭裡就好。
- **資產圖的細節**寫在 `detail`（角色、造型、場景、機位、道具、特效都有）：做工、材質、磨損與陳設，只進設定圖、頭像、表情組圖、場景定稿圖、機位背景圖、道具圖與特效參考圖，不進鏡頭。鏡頭的片段要精簡，參考圖卻要細；不寫的話資產圖只有鏡頭用的那幾個字，畫出來很單薄。不寫新的辨識特徵，寫法見 `references/prompt-writing.md` 的 `detail` 一節。
- **媒材是真人寫實時**填 `project.medium: "真人寫實"`：腳本會把角色設定圖改成攝影棚的定妝照、場景定稿圖改成實景照片，寫實的鏡頭才不會掛著一張插畫當參考。外貌寫真人的樣子（膚質、年齡痕跡、髮際線），不寫「完美無瑕」「精緻五官」這類會變成塑膠臉的詞，也不用真人演員的名字。寫法見 `references/prompt-writing.md` 第八節。
- **非人角色**（妖怪、會說話的動物、成精的器物、巨獸）填 `kind`。人形與原形長得不一樣時，每個形態開一個造型變體，各寫自己的 `look` 與 `tag`；沒有嘴的角色填 `mouthless`。大小拿人來比，不要只寫神話名稱。
- **特效**（法術、印記、妖氣、會一集一集變化的記號）登記在 `effects`，鏡頭裡用 `fx` 引用；會變化的把每個階段寫在 `states`。`make` 決定在生成時做還是後製做。非人角色與特效的寫法見 `references/creatures-and-effects.md`。
- **風格鎖定句**寫媒材或畫風、線條、上色方式、飽和度與對比、質感；真人寫實寫片種與攝影質感（「電影感寫實攝影，35mm 膠片質感，輕微顆粒，低飽和」）。它會被加到每一張圖，包含純色背景的角色設定圖、沒有人的場景圖與道具圖、夜戲和回憶，所以不要在裡面提背景、人物（連皮膚、臉也不寫，膚質寫在角色的 `detail`）、天氣、光線方向，也不要寫冷暖或主色（「暖色調」「偏青藍」）：一到夜戲或回憶，提示詞裡就會同時有「暖色調」和「冷白的月光」。
- 四個欄位各管各的，不要重複：`light` 管光源、方向、明暗與光本身的顏色；`time` 管時間與天氣；`palette` 管這個場景整體的色彩（主色、暗部偏什麼色、點綴色），只寫光線沒說到的；飽和度與質感歸風格鎖定句。每個場景的 `palette` 排在一起看，就是這一集的色彩腳本。
- **要避開的東西先寫成要什麼。**「空蕩的街道」比「沒有人的街道」穩，「兩隻手的位置」比「不要多餘手指」穩，這在任何工具上都成立。`negative_global` 是給有獨立負面詞欄位的工具用的：工具未定時可以先寫一組通用的負面詞，它單獨列在一個欄位，不會混進正向提示詞；定了工具、而它沒有負面詞欄位，就清空。
- **原文沒寫的外貌或場景**：補一個具體的暫定值寫進設定，並列入 `pending`（待確認）。留空的話生成工具會自己猜，而且每鏡猜得不一樣；暫定值至少前後一致。原文自相矛盾時也一樣：選一種處理，列入待確認。

設定檔裡的片段會進到每一鏡的提示詞，寫得不好會錯一整部。外貌、服裝、光線、風格鎖定句各自的寫法、用詞與好壞對照見 `references/prompt-writing.md`，寫設定檔前讀。最重要的一條：只寫看得見的東西，「氣質清冷」「溫馨的房間」這類形容畫不出固定的樣子。

### 4. 估篇幅，決定要不要先停

**一章一集。** 沒有指定單集長度時，原文一章就是一集（一個 `EPxx.json`），長短由故事決定，不設片長或鏡數上限。使用者指定別的範圍（「只拆前半章」「這三場算一集」）就照做。一次最多處理一章：貼了好幾章時從第一章做起，交付時說明下一步接哪一章。

**有單集長度，或輸入是大綱時**，集數由分集表決定，什麼時候停下來確認也照 `outline-to-episodes` 第二節的三個確認點，不用下面的規則。

**估鏡數**：先把每場戲分成節拍（有人做了新的事、出現新資訊、情緒轉向，各算一個），再數每個節拍裡的動作、對白、反應，各算一鏡。字數只能粗略參考，敘事密的文字大約 15 到 30 字就是一鏡，所以一千字的章節常常有四五十鏡。把每鏡的預估秒數加起來，就是預估片長。估完用字數驗算一次：平均每鏡不到 15 字，通常是把每個小動作、每一眼都拆成了一鏡，回頭把同一個節拍裡的小動作合併；超過 30 字，多半是漏了反應鏡頭。各場的預估加起來要等於整章的總數。

**要不要先停：**

- **只有一個地點，而且估計在 30 鏡以內**：一次做完，暫定設定列在最上面請使用者確認。
- **不只一個地點，或估計超過 30 鏡**：先交第一階段，停下來等使用者確認，再拆鏡。參數在第二步已經問過了，這一次確認的是角色與場景設定和場景清單：拆了幾十鏡才發現某個角色或某場戲不對，要重做的量最大。外貌、風格和工具之後再改沒關係，改設定檔重跑腳本就好。
- **使用者事先說「直接做完」「一次做完」就不停**，把整章做完。這句話只跳過這裡的確認關卡；第二步的參數問題，要使用者說「不用問」「你決定」才跳過。

第一階段只跑 `bible.json`，腳本會產出 `settings.md` 與 `assets.csv`。對話裡的回覆依序是：

1. 本次參數（第二步確認過的），以及還沒決定、先用建議值的地方。
2. 場景清單：每場的地點、發生什麼、這場戲的目的與高點、預估鏡數與秒數，以及整章的預估片長。
3. 角色與場景設定表，分清楚哪些來自原文、哪些是暫定。
4. 資產清單（要先生成哪些圖、各用什麼畫幅），提示詞本體在 `settings.md`，不用貼出來。腳本會替每個角色出全身四視圖的設定圖（含四分之三側面），人與半人另出一張頭像（臉部特寫），有狀態的道具每個狀態另出一張由原圖改出來的圖。
5. 請使用者確認或修改，說明確認後下一步做什麼。

回覆裡提到的表和清單要真的貼在回覆裡。寫了「待確認設定見下方」，下方就要有那張表；只放在檔案裡的，寫明檔名。回覆裡的數字（鏡數、秒數、資產張數、原文字數）照檔案和腳本的輸出寫，不要憑印象。

### 5. 拆鏡

順序是場次 → 節拍 → 鏡頭。方法與理由在 `references/shot-craft.md`，拆鏡前讀；下面是要點。

**先寫場次設計（`plan`），再拆鏡頭。** 每場戲先回答：這場戲的目的是什麼、觀眾跟著誰看（視點）、分成哪幾個節拍、高點在哪個節拍。景別、鏡頭長短、停留在哪裡，都從這四個答案來。跳過這一步直接把句子翻成鏡頭，會變成原文一句對一鏡，每鏡一樣重，看不出重點。兩個以上角色同場時，再寫走位（`blocking`）：每個人在空間裡從哪裡開始、往哪裡移動，軸線在誰和誰之間。用門、窗、桌子當參照，不用畫面左右；機位和每一鏡的左右位置都從這裡推出來。

**每一鏡用 `beat` 指回它拍的節拍**（`"1.3"`＝第 1 場的第 3 個節拍）。腳本靠它檢查：每個節拍都有鏡頭、高點有沒有拿到最近的景別和最長的停留、是不是每個節拍都只有一鏡。

**每鏡一個主動作，有明確的起點和終點。** 起點寫在走位（首幀），終點寫在 `end`（結束時的畫面）。一個連續的動作可以有前後幾拍（起身、走到窗邊），順序寫清楚就好；兩件互不相干的事放在同一鏡，觀眾抓不到重點，生成工具也通常只做對一件。

**鏡頭語言**
- 一個鏡頭怎麼拍，分四個欄位填：景別（`size`，取多大）、鏡頭類型（`type`，過肩、主觀、空鏡、插入等）、角度（`angle`）、運鏡（`camera`）。過肩鏡頭也要有景別。需要時再填機位高度（`height`）、焦段（`lens`，廣角、長焦、35mm，真人寫實最常用）與速度（`speed`，升格、定格等）。用詞與各自的取景範圍見 `references/fields.md`。
- 景別跟著情緒走，不是為了變化而換。一場戲通常由遠到近；最近的景別和最長的停留留給高點，特寫省著用。
- 場景出現後的頭三鏡內，要有遠景或全景交代空間。
- 對白不是誰說話就拍誰。說話者和聽的人的反應交替；一句話的後半常常落在聽的人臉上，這時 `line` 用「畫外音」。過肩正反打的兩邊景別成對，連續幾鏡同景別是正常的。
- 連續兩鏡拍同一個主體時，景別至少差一級或換角度，否則畫面像跳了一下（跳接）。
- 運鏡預設固定，要動就要有理由。帶方向的運鏡寫出方向：「左移」，不是「橫移」。

**機位（`setups`）**：對話戲和任何來回切的戲，先定兩到四個機位，背景寫在機位上，鏡頭用 `setup` 引用。同機位的鏡頭背景才會一字不差，軸線有沒有守住也一眼看得出來。腳本會替每個機位出一張機位背景圖（沒有人物的空景），當這個機位所有鏡頭的背景參考；場景定稿圖只有一個角度，反打看到的牆不在那張圖裡。

**時長跟著內容走**，長短要有變化；各形式常見的單鏡長度見本節最後的表。
- 中文旁白或對白大約每秒 4 到 5 個字。腳本的算法是「字數 ÷ 4.5 + 0.3 秒」，標點不算；英文約每秒 2.8 個詞。句子塞不進去就縮短句子、拆成兩鏡，或把一句話分到相鄰兩鏡的 `line`。
- `duration` 是成片裡用的長度。工具單次能生成幾秒、頭尾要裁多少，是工具定了之後的事。

**速度與力道照故事寫。** 打下去的一拳、摔門、撲過去，`motion` 就照實寫出速度與力道；這一下要讓觀眾看清楚，用 `speed` 的升格。反過來，不要每一鏡都寫「緩慢」：整片像慢動作，本身就是常見的 AI 感。定了工具、它做不好快速的動作時（`tool_limits.fast_motion` 是 `false`），再把這類鏡頭拆成預備、結果與反應，速度交給剪接，見 `references/anti-ai-rules.md` 第二部分。

**銜接**（`link`）：絕大多數鏡頭是「切」，各自生成首幀圖。只有同一機位、同一批角色、動作直接延續時才用「接續」，表示拿上一鏡的最後一幀當這一鏡的首幀。全部都用接續會變成沒有剪接的長鏡頭，誤差還會一路累積。

**轉場**（`transition`）：`link` 是怎麼生成，`transition` 是怎麼剪。不填就是硬切，多數鏡頭如此。動作剪輯、匹配剪輯、疊化、聲音延後這幾種需要前後兩鏡的畫面事先配合，所以在拆鏡時就要決定，見 `references/fields.md` 的轉場表。

**難拍的鏡頭先照戲寫，風險記下來。** 打鬥、奔跑、多人肢體接觸、手部特寫、拿取小物件、轉身、變身、法術對打、大量人群，是生成工具比較容易做壞的鏡頭，但每個工具強弱不同。工具未定時，照這場戲需要的拍法寫，在 `risk` 寫一句這一鏡難在哪裡、做壞了的備案；定了工具，再照它做不好的地方換拍法（用剪接、遮擋、背影、影子、反應鏡頭或物件特寫），替代表見 `references/anti-ai-rules.md`。

**動作戲**：先用一個全景交代場地和雙方的位置；攻守兩方固定在畫面兩側；每一擊有預備、出手、結果，觀眾看得懂誰佔上風，靠的是結果與反應。結果要看得出是誰做的：出手的人收勢的姿勢，或被打的人看向他，至少一樣入鏡。一個回合一個節拍，每回合都改變局勢，而且一回合比一回合近、鏡頭比上一回合短。見 `references/shot-craft.md` 第十節。

**揭示**：想讓觀眾緊張，就讓他們比角色先知道；角色看見了什麼，先拍他的反應，再拍他看見的東西；反應和揭示放在同一個節拍，緊接在看見之後。反應鏡用近景或特寫，要看得清楚臉色怎麼變；中景以外的反應等於沒有反應。漫劇與短劇的卡點停在反應上，答案留到下一集。見 `references/shot-craft.md` 第十一節。

**畫面裡要讀得懂的字**（招牌、信件、手機訊息、彈幕）：短的字（招牌上兩三個字）照寫進提示詞，用引號標出要寫的字。長的內容（訊息、信件、介面）本來就適合後製加：好改、好讀、能換語言，在 `post` 註明。後製要把字貼上去，所以那一鏡裡寫字的物件要穩：手機、信紙保持靜止，螢幕或紙面朝向鏡頭、沒有被擋住；物件非動不可時，在 `post` 註明字要做追蹤。替字留位置時，片段只寫看得見的空白（「螢幕亮著，畫面是空白的」），不要寫「給後製的字」：「後製」「字幕」這些字眼進了提示詞，工具反而會去畫字，腳本會警告。定了工具、它寫不好字時（`tool_limits.text` 是 `false`），短字也改成後製。

**光線在同一場戲裡改變**（熄燈、閃電、車燈掃過）：用那一鏡的 `light` 覆寫，不必另開場景編號。光的顏色變了（暖色的燈籠光、紅色的警燈），場景的 `palette` 很可能和它矛盾，這時連 `palette` 一起覆寫。時段真的換了、而且之後很多鏡都是新光線，才開新場景。

**時間跳躍和回憶**要標出來：進出各用一個轉場（疊化、黑場或閃白），另開場景編號寫不同色調的光線，角色用當時的造型變體。

**標建議切點**（`cut`）：只用在漫劇與短劇，而且沒有指定單集長度的時候。一章是一整集，使用者之後可能自己切成較短的片段，在適合切開的鏡頭上寫 `cut` 和一句理由，腳本會算出累計時間並列成清單。
- 好的切點：一場戲結束、懸念或揭露之後、情緒落點、時間跳躍之前。不要切在一句對白、一問一答，或一個連續動作的中間。
- 分布大致平均，約每三十秒到一分半鐘有一個。最後一鏡不用標。

**不改劇情。** 每一鏡填 `source`（原文的一小句或段落號），使用者才能核對有沒有漏。刪減、合併、新增、調動順序都寫進 `changes`，並在交付時說明。

**依形式調整：**

| | 漫劇 | 短劇 | 動畫 | 真人劇 | 影片（MV、廣告） |
|---|---|---|---|---|---|
| 推進 | 旁白為主，畫面配合旁白 | 對白與衝突，強反應 | 對白與表演 | 對白與表演，容許沉默 | 配樂或旁白 |
| 單鏡長度 | 2 到 4 秒 | 1.5 到 4 秒，最快 | 3 到 6 秒 | 3 到 8 秒，可以更長 | 跟著音樂的拍子 |
| 開頭 | 前 3 秒先給衝突或懸念 | 前 3 秒先給衝突或懸念 | 可以用建立鏡頭開場 | 可以用建立鏡頭開場 | 前幾秒給最強的畫面 |
| 結尾 | 停在懸念上 | 停在卡點的反應上 | 依原文 | 依原文 | 品牌、標題或情緒落點 |
| 景別 | 近景與特寫為主，一鏡一個主體 | 近景、特寫與反應鏡頭最多 | 遠中近搭配 | 遠中近搭配，可用長焦與景深 | 看創意 |
| 靜幀 | 空鏡、物件、旁白段落可以用 | 少用，只有定格與字卡 | 不用 | 不用 | 看風格 |

- **漫劇與短劇的開頭鉤子**：先從原文開頭找最有張力的細節當第一鏡（一個特寫、一件道具），接著再給全景。原文開頭平淡時，可以把後面的一句話或一個畫面提前當預告，但這算改動：記在 `changes`，交付時說明，並告訴使用者不要的話刪掉那一鏡即可。提前的那一鏡，`beat` 照實填它原本所屬的節拍。它是多出來的一鏡：它拍的內容在原本的位置也要有一鏡交代，使用者刪掉鉤子時劇情才不會缺一塊。
- **漫劇的靜幀**：空鏡、物件特寫、旁白段落、要後製加字的畫面，可以填 `render: 靜幀運鏡`：只出首幀圖，剪接時在圖上推拉或搖移，不跑影片、成本低。角色在表演或說話的鏡頭仍然用影片。定格、集中線、花字這類後製效果寫在 `post`。見 `references/shot-craft.md` 第十二節。
- **短劇**：衝突要早、反應要大、資訊要快；爽點的「看」（旁人的反應）一定要拍，人物出場可以定格加名字字卡。見 `references/shot-craft.md` 第十四節。
- **真人寫實**：鏡頭語言照真的攝影來（焦段、景深、自然光的方向），表演要小、要有不完美的細節，最大的 AI 感是塑膠皮膚與太完美的臉。見 `references/prompt-writing.md` 第八節與 `references/anti-ai-rules.md` 第一部分。
- **9:16**：以單人構圖為主，用前後縱深代替左右並排；雙人戲用過肩或交替單人，不要硬擠並排。平台的介面和字幕會蓋住畫面上緣約一成、下緣約兩成、右緣約一成（概略值），臉和關鍵道具放在中間這一塊。**16:9 與更寬的畫幅**：可以並排雙人，注意左右軸線一致。
- **旁白**：角色不開口，表情欄寫「嘴唇自然閉合」，鏡頭長度跟著旁白句子。敘事的句子 `type` 用「旁白」；角色的台詞照常填「對白」或「畫外音」、`who` 填角色編號，由配音蓋在畫面上。
- **後配口型**：對白鏡頭用固定機位，臉朝鏡頭方向，嘴部不被遮擋，頭部動作小；生成時嘴唇閉合，口型之後另外做。
- **原生音訊**：對白與聲音由腳本寫進影片提示詞，所以 `sound` 和台詞的語氣（`line.tone`）要用提示詞語言寫。一鏡只讓一個人說一句話；只有說話者正面入鏡的「對白」會進提示詞，「畫外音」在剪接時鋪。每個角色的聲線寫在設定檔的 `voice`，腳本會把它寫進這個角色的每一句台詞，否則每一鏡的聲音會不一樣；工具有音色庫或能上傳聲音樣本時，選定的名稱寫在 `voice_ref`。

### 6. 寫分鏡檔，執行腳本

把分鏡寫成 `storyboard/EPxx.json`，鏡號用 `EP01-001` 這種格式，換集不重號。然後執行：

```bash
node <這個 skill 的資料夾>/scripts/build_storyboard.mjs storyboard/bible.json storyboard/EP01.json
```

**一集有兩場以上時，一場一場寫。** 一次寫幾十鏡，後段容易變敷衍、漏欄位，甚至被輸出長度截斷。做法：

1. 先寫第一場的鏡頭，執行腳本，修到沒有錯誤。
2. 寫下一場前，看上一場最後一鏡的 `end` 和 `continuity`，確定人物、道具、光線怎麼接。同一場裡也一樣：上一鏡放在櫃檯上的手機，下一鏡還在，除非有一鏡（或 `end`）交代它被拿走。
3. 用編輯檔案的工具把下一場的鏡頭接到同一個檔案的 `shots` 尾端，不要整檔重寫。再執行腳本。
4. 全部寫完後最後跑一次，看整集的片長和節奏。

單一場超過約 30 鏡時，也拆成前後兩段寫。分批只是寫的方式，仍然是同一集、同一個檔案。

產出在 `storyboard/out/`：`settings.md`、`assets.csv`、`EP01-storyboard.md`、`EP01-shots.csv`、`EP01-animatic.csv`（動態分鏡的時間線）、`EP01.srt`（臨時字幕），有機位時另有 `EP01-assets.csv`（這一集的機位背景圖）。CSV 可以直接用 Excel 開。「驗收重點」由腳本產生；模型、seed、抽卡次數、採用版本、驗收結果、備註留空給使用者記錄生成狀態。

**重跑不會清掉使用者的紀錄。** 腳本重跑時會先讀舊的 CSV，按鏡號（資產按編號、類型與語言；只換了提示詞語言時按編號與類型）把手填的欄位、使用者自己加的欄位、沒有欄名的欄和重複欄名的欄（加上「(2)」）搬到新檔，`EP01-animatic.csv` 也一樣。同一個鏡號有好幾列（複製一列記第二次抽卡）時，每一列都保留；標題列上面多插的說明列會略過。舊檔或已移除檔讀不懂時（被另存成別的格式），那個 CSV 這次不更新，會說明要另存成「CSV UTF-8」或把檔案移走。內容有變才把舊檔備份到 `out/備份/`：每個檔案留最近五份，另外留最近七個有備份的日子各一份。刪掉或改了鏡號的鏡頭，紀錄移到 `EP01-shots-已移除.csv`，鏡號回來時再搬回去。CSV 在 Excel 裡開著時腳本寫不進去，那個檔案和它的已移除檔這次都不動，會說明是哪個檔案、請使用者關掉再跑，其他檔案照常更新。提示詞欄位不要在 CSV 裡改，改分鏡檔或設定檔再重跑，否則下次會被蓋掉。

**集數決定檔名。** 分鏡檔的 `episode` 要和檔名一致（`EP02.json` 就寫 `EP02`），鏡號也用它開頭。複製上一集的檔案來改時最容易忘：`episode` 和檔名的集數對不上時，腳本報錯、不寫出這一集的產出，免得蓋掉別一集的分鏡表和 CSV 紀錄。

第二個參數也可以是分集表或分集劇本：給 `series.json` 會產出 `series.md` 並檢查分集表；給 `EP01-script.md` 會算台詞長度、檢查說話者，不寫檔案。`bible.json` 旁邊有 `series.json` 時，分鏡表最上面會列出這一集的鉤子、爽點與卡點，並用 `episode_length` 檢查整集長度。

寫提示詞片段時記得腳本怎麼組合，才不會重複或矛盾。每種片段怎麼寫才好（走位、背景、構圖、動作、語氣，以及英文片段的寫法）見 `references/prompt-writing.md`。

- **首幀圖像提示詞** ＝ 角色外貌與造型 ＋ 朝向與走位（`facing`、`pos`、`gaze`、`hands`、`face`）＋ 道具 ＋ 背景 ＋ 光線與色彩 ＋ 景別、鏡頭類型、角度、高度、焦段與構圖 ＋ 風格鎖定句。
  - **參考圖模式**下，角色寫成「圖1中的＋短稱」，近景以內再加「（臉部參照圖2）」指向頭像，背景寫成「背景參照圖3：＋這一鏡的 `bg`」，道具在描述後面註明（圖4），道具寫了狀態就指向那個狀態的圖。長相交給參考圖，文字不再重複整段外貌，兩邊才不會互相拉扯。參考圖的順序由腳本決定，列在每一鏡的生成資料裡，使用者照順序上傳。
  - 兩種模式都由腳本列出這一鏡的角色設定圖（近景以內加頭像）、背景圖、道具圖與特效參考圖，`refs` 只寫額外要掛的圖（表情組圖、前一鏡的首幀）。
  - 景別會連同取景範圍一起寫進去（「中景，腰部以上入鏡」），所以景別要和這一鏡要看到的東西對得上：要看到踏步就不能填中景。
  - 近景以內要有 `bg`（這一鏡實際看得到的背景；自己填，或由機位提供），否則腳本會放整段場景描述，生成工具可能把整個房間塞進特寫。
  - 場景的光線會進每一鏡。特寫裡看不到的光源（「從屋頂破洞照下來」）會誤導生成工具，這種鏡頭用 `light` 覆寫成畫面上看得到的光。
  - 朝向用 `facing` 的用詞（正面、半側朝左、側面朝右、背面⋯），不要寫在 `pos` 的自由文字裡；正反打的兩個人方向相反。表情寫看得見的眉、眼、嘴與呼吸，不要只寫「難過」，寫法見 `references/prompt-writing.md` 的情緒對照表。
  - 只有背影或前景虛焦的角色設 `partial: true`；只入鏡一隻手或一雙腳時，把 `partial` 寫成看得到的那一部分（「一隻從畫面右緣伸入的手，袖口是米白色毛衣」）。
- **尾幀** ＝ 一句圖像編輯指令：拿首幀圖當底，改成 `end` 描述的結束畫面。從首幀改出尾幀，比重新生成一張更能保持角色和場景不變。
- **影片提示詞**（圖生影片）＝ `motion` ＋ 運鏡，不含外貌。首幀圖已經決定了長相，這裡再描述一次，反而容易讓工具重新詮釋而走樣。所以 `motion` 只寫怎麼動：主動作、它的起因、一兩個微動作（眨眼、呼吸）、有原因的次要運動（風吹動窗簾）。原生音訊方案下，腳本會在後面接上台詞與 `sound`。
- **畫幅不在提示詞裡**，是生成工具的選項，交付時提醒使用者選對。鏡頭與機位背景圖用影片畫幅；資產圖各有建議畫幅，寫在 `settings.md` 每張圖的標題後面與 CSV 的「建議畫幅」欄（設定圖與組圖 16:9、頭像 3:2、道具與特效 1:1）。工具要把參數寫在提示詞最後的（Midjourney），填 `project.image_suffix: "--ar {ar}"` 與 `asset_suffix: "--ar {ar}"`，腳本會把 `{ar}` 換成每一張圖的畫幅。

### 7. 處理檢查結果，再請三個角色審查

腳本會檢查機械性的問題：編號對不上、漏填走位、對白超過鏡頭長度、跳接、運鏡沒有方向、近景沒有背景、用詞不在用詞表、場景描述用了畫面左右、風格鎖定句寫了冷暖、節拍沒有鏡頭、高點沒有用最近的景別或最長的停留、多人的戲沒寫 `blocking`、有台詞的角色沒寫聲線等等。和工具有關的檢查（單次秒數、提示詞長度、參考圖張數、負面詞、畫面文字、快速動作、複雜運鏡）只在填了對應的工具欄位之後才會跑。「錯誤」必須修；「警告」修掉，或有理由保留時在交付中說明；「提示」自行判斷。改完重跑到乾淨為止。

裝成 plugin、而且工具支援 hook 時，改了 `bible.json`、`EPxx.json`、`series.json` 或分集劇本，腳本會自動跑一次，錯誤與警告直接回到對話裡。沒有 hook 的環境照樣自己執行；hook 只是保險，有沒有它都要看檢查結果。

檢查乾淨只代表沒有機械性錯誤。腳本看不出來的分成四份看，像真的劇組一樣：各部門提意見，導演拍板。

- **導演（你自己）**：照 `references/anti-ai-rules.md` 第七節「導演自己看」那一段：鏡頭安排有沒有照著場次設計（高點是不是最近、停最久）、揭示的順序、每一鏡是不是真的只有一個主動作、原文有沒有漏。也打開產出的 `settings.md` 看一眼組合後的資產提示詞有沒有自相矛盾。
- **攝影與連戲、表演、美術**：整集寫完、腳本乾淨之後，請三個審查角色各看一次。每一個都要讀完整集，所以一集審一次，不要每寫完一場就審。
  - **能開子代理時**，三個同時開。Claude Code 裝了這個 plugin 時，用 `storyboard-camera-reviewer`、`storyboard-acting-reviewer`、`storyboard-art-reviewer` 三個代理；其他環境（例如 Codex）開一般的子代理。每一個都給完整路徑：它的審查檔（這個技能資料夾裡的 `references/review-camera.md`、`references/review-acting.md`、`references/review-art.md`）、`bible.json`、這一集的 `EPxx.json` 與 `out/EPxx-storyboard.md`，並說明只回報、不改檔。三個同時改同一個檔案會互相蓋掉。
  - **不能開子代理時**（例如 claude.ai 的聊天）：自己照三份審查檔各走一遍，一次只看一份，只帶著那個角色的眼光看。
- **收回意見後由你拍板**：照場次設計裡這場戲的目的取捨。兩個角色的意見衝突時（攝影要遠景交代空間、表演要近景看臉），以這一場的目的和高點為準。採用的改分鏡檔或設定檔，改完重跑腳本；沒採用的「必改」項，交付時說明理由。

自查或審查時改了設定（風格鎖定句、外貌、場景），`pending` 裡對應的那一條和分集表裡的描述也一起改。

### 8. 交付

在對話裡給：

1. 本次參數和待確認設定（第二步沒回答、先用建議值的參數也列在這裡）。工具未定時說一句：提示詞是不限工具的完整版，選定工具後告訴你，會照那個工具的長度、秒數和弱點改一次。
2. `EPxx-storyboard.md` 開頭的精簡表（鏡號、秒、累計時間、景別、動作、對白、切點），直接貼。場次設計、機位表與完整的導演表請使用者開檔案看。
3. 對原文的改動，有風險的鏡頭與備案，以及保留未修的檢查項目和原因；審查角色的「必改」沒有採用的，也說明為什麼。
4. 檔案位置，以及建議的製作順序：先生成並定稿資產圖與機位背景圖，再出首幀（記得選對畫幅）；首幀出完後，用 `EP01-animatic.csv` 把首幀排上剪輯軟體的時間線、匯入 `EP01.srt` 配臨時配音，粗剪一版看節奏、軸線和長度，確認了才生成影片（影片最貴，問題在這裡抓最便宜）。每一步怎麼驗收、生成不好時怎麼改，見 `references/generation-qa.md`，交付時挑一兩句和這一集有關的說。

提示詞本體不用貼進對話，使用者要看哪一鏡再貼。它們很長，而且檔案裡的版本才能直接複製。

做完一集，在 `bible.json` 的 `log` 加一行收尾狀態（誰在哪裡、穿什麼、道具狀態、時間），下一集從這裡接戲。

## 換工具、修改、生成結果不對

選定或換了工具、要修改已經做好的分鏡、使用者回報生成結果不對時，照 `storyboard-fix` 技能做（`../storyboard-fix/SKILL.md`）。同一個對話裡剛交付的分鏡要小改，也照它的「修改既有分鏡」一節：插入鏡頭用 `EP01-004a` 這種鏡號，不要重編後面的號碼。

## 沒有程式執行環境時

不能執行腳本時，照 `examples/out/` 兩個檔案的版面直接在對話輸出：設定表寫一次，接著是精簡表，然後每一鏡的提示詞放在各自的程式碼區塊裡完整展開，不留 `[角色描述]` 這種佔位符，因為使用者要能直接複製。一次輸出一個場景，免得中途被截斷。然後依 `references/anti-ai-rules.md` 第七節的清單逐項自查，包含腳本原本會代勞的那些，再照第七步的三份審查檔各走一遍。

- `examples/creature-fx/`：一場茶館夜戲的完整範例與產出（中文提示詞、漫劇 9:16、後配口型），示範半人狐妖的兩個形態、用影子拍變身、沒有嘴的茶壺怎麼說話、分階段的掌心印記，以及後製才加的特效。有非人角色或特效時讀。
