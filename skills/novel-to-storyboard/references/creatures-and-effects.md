# 非人角色與特效

`prompt-writing.md` 的外貌寫法是給人類角色的。妖怪、會說話的動物、成精的器物、巨獸，以及法術、印記、妖氣這些特效，還要多決定幾件事：大小怎麼比、變身怎麼拍、沒有嘴的角色怎麼說話、特效在生成時做還是後製做。

完整範例在 `examples/creature-fx/`：一個會變身的半人狐妖、一把會說話的茶壺、會隨劇情變化的掌心印記，以及一個後製才加的特效。

## 一、非人角色

### 先分類：`kind`

| `kind` | 例 | 外貌怎麼寫 | 腳本的差別 |
|---|---|---|---|
| `人`（預設） | | 照 `prompt-writing.md` | |
| `半人` | 長著狐耳的女子、腰部以下是蛇尾的男子、額頭有角的少年 | 人形部分照人類寫，非人的部位放在最後：長在哪裡、多大、什麼顏色與質感 | 和人一樣，要寫服裝 |
| `動物` | 會說話的黑貓、狐狸、烏鴉 | 物種、體型、毛色與花紋、眼睛、一個辨識特徵 | 服裝可以空；鏡頭裡 `hands` 不強制（有前爪的動作再寫） |
| `器物` | 燈籠精、紙人、茶壺精、木偶 | 器物本體：材質、形狀、大小、新舊、顏色；有臉的話，臉在哪裡 | 服裝可以空；鏡頭裡只要寫 `pos` |
| `異獸` | 比人大的妖獸、神獸、怪物 | 見下一節的順序 | 服裝可以空；設定圖自動加一個人類剪影當比例尺 |

`動物`、`器物`、`異獸` 沒寫 `expressions` 時，腳本不產出表情組圖：預設的「平靜、微笑、難過、生氣」對它們沒有意義。

### 異獸與動物的外貌順序

原型（像什麼動物）→ 和人比的大小 → 姿態（四足、直立、盤繞、漂浮）→ 表面（皮、毛、鱗、甲的材質、顏色與花紋）→ 特徵部位（角、尾、翅膀，寫出數量和位置）→ 眼睛。

| 不好 | 好 | 差在哪裡 |
|---|---|---|
| 威猛的上古凶獸饕餮 | 一頭比成年人高一倍的四足巨獸，身形像肥壯的野牛，青黑色厚皮上有深色雲紋，頭頂一對向後彎的短角，嘴巴一直裂到耳根，眼睛長在頭頂兩側 | 「威猛」「上古」畫不出來；神話名稱每個工具理解不同 |
| 九尾狐 | 一隻比成年人略高的白狐，蹲坐，長毛蓬鬆，身後九條尾巴像扇子一樣展開，尾尖淡金色，琥珀色的細長眼睛 | 寫出大小、數量、排列和顏色 |
| 會飄的燈籠精 | 一盞直徑約四十公分的紅色紙燈籠，竹骨，上下是黑色木框，紙面有一道舊的修補痕 | 器物精寫器物本體；「會飄」是動作，寫在 `pos` 或 `motion` |

- **不要只寫物種或神話名稱。** 饕餮、九尾狐、獬豸這類名字，有的工具畫成傳統紋樣，有的畫成卡通，有的直接忽略。名字留在 `name`，`look` 寫看得見的特徵。理由和不寫真人的名字一樣。
- **大小拿人來比**：「比成年人高一倍」「坐下時和站著的人一樣高」「只有巴掌大」。「巨大」「小小的」沒有比例，每一鏡會畫成不同大小。和人同框的鏡頭，`pos` 也寫相對高度：「巨獸的頭在女子頭頂上方一個頭的高度」。
- **數量寫清楚，但越少越好。** 九條尾巴、三隻眼、六隻腳，生成工具常常數錯或長歪。能用一個顯眼的特徵代表，就不要三個。數量多的部位不要每一鏡都完整入鏡，改用背面、局部、剪影或影子，並在 `risk` 註明生成後要數一下。
- **短稱用最顯眼的非人特徵**：「銀髮狐耳的女子」「右耳缺角的胖黑貓」「壺嘴有缺口的紫砂壺」。和人類角色的短稱放在一起，要一眼分得出來。

### 人形與原形：每個形態開一個造型變體

變身前後長得完全不一樣時，每個形態開一個造型變體，各寫自己的 `look` 和 `tag`：

```json
"variants": [
  {"id": "C02-a", "label": "人形", "outfit": "月白色長披風，裡面是淺灰色交領長裙", "outfit_top": "月白色長披風，裡面是淺灰色交領上衣"},
  {"id": "C02-b", "label": "原形", "look": "一隻比成年人略高的白狐，蹲坐，長毛蓬鬆，身後三條大尾巴像扇子一樣展開，琥珀色的細長眼睛", "tag": "三尾白狐"}
]
```

- 有自己 `look` 的形態，腳本會出一張完整的設定圖，不會拿人形的圖來改（人形改不出狐狸）。比人大的原形，在 `sheet` 寫上「旁邊站著一個灰色的成年人剪影作為比例參考」。
- `marks` 會加在每一個形態上，所以寫**每個形態都有的記號**：同一個顏色的眼睛、同一撮異色的毛、同一條紅繩。觀眾靠它認出這是同一個角色，生成工具也靠它把兩個形態連起來。只屬於某個形態的特徵，寫進那個形態的 `look`。
- 半變身（只露出尾巴、眼睛變色）通常只是人形多一點東西：開一個造型變體，`outfit` 照舊，在 `state` 寫多出來的部分（「身後露出一條銀白色的狐尾」）。

### 表情與表演

- **動物和異獸**的情緒在耳朵、尾巴、毛、瞳孔和姿勢：耳朵往後貼（害怕、生氣）、尾巴膨起（受驚）、瞳孔放大（專注、興奮）、壓低前身（戒備）。`expressions` 和 `face` 寫這些，不寫「微笑」。
- **器物**沒有臉，情緒在材質和光：燈光變亮、紙面起皺、壺蓋抖動、表面冒出水珠。`expressions` 寫成這些狀態，`face` 留空。
- **半人**的臉照人類寫，非人的部位可以幫忙：狐耳往後貼比眉頭緊皺更好認，也更穩。

### 沒有嘴的角色說話

在 `bible.json` 填 `"mouthless": true`。這種角色說話時：

- `line.type` 用「畫外音」。生成工具不會替燈籠對口型，硬要它做，常常在紙面上畫出一張嘴。腳本看到沒有嘴的角色用「對白」會提示。
- `motion` 寫一個看得見的說話信號，觀眾才知道是它在說話：燈光隨話語一明一暗、紙片輕輕顫動、壺蓋輕輕跳動、壺嘴冒出一縷白氣。
- 配音時給它一個固定的聲線，和其他角色差得夠遠。

會說話的動物有嘴，但嘴型和人不一樣，對口型工具是為人臉設計的，未必對得上。後配口型時，讓它說話的鏡頭多用背面、遠景或拍聽的人；原生音訊時照常寫對白，多抽幾次。

### 變身

完整的變身過程是難拍的鏡頭：身體在一鏡裡從一種形狀變成另一種，多數工具很難一次做對。想讓觀眾看到完整的「變」，照實寫一鏡，在 `risk` 寫下面的三步當備案；不必看到過程的，直接拆成三步，這也是實拍常用的做法：

1. **變身前**：人形的近景，給一個預兆：瞳孔變色、狐耳豎起、周圍起風、燈光暗下來。
2. **遮擋或轉場**：閃白、一陣煙或光把人整個蓋住，或切到旁人的反應。
3. **變身後**：原形的鏡頭，用原形的造型變體，各自生成首幀。

想讓觀眾看到「變」的過程，拍影子：牆上的人影慢慢舒展、長出尾巴的影子。影子是平面的剪影，沒有臉和手要維持，比立體的身體穩定。影子在 `cast` 裡用原形的造型變體，`partial` 寫成那個影子（「牆上一個巨大的狐狸影子，三條尾巴的影子在身後展開」）。

## 二、特效

### 分哪幾種、在哪裡做

特效登記在 `bible.json` 的 `effects`，用 `make` 說明在哪裡做：

| 類型 | 例 | `make` |
|---|---|---|
| 附在角色或道具上、會跨集變化 | 掌心的印記、燒到一半的香、越來越長的裂痕 | `生成`，每個階段登記在 `states` |
| 柔和的能力與法術 | 催眠的光環、漂浮的鬼火、擋在門口的光牆 | `生成`，或 `生成加後製`（後製再加亮、加光暈） |
| 環境異象 | 妖氣、霧、燈自己亮起 | `生成` |
| 文字、數字、介面 | 計數器、跳出的數字、浮現的咒文 | `後製` |
| 快速、大範圍的爆發 | 爆炸、衝擊波、法術對轟 | `生成`；選定的工具做不好快速的動作時改 `後製`，或用閃白、反應鏡頭代替 |

判斷的原則：生成工具最穩的，是**柔和、緩慢、沒有精確形狀**的東西：光、霧、煙、粒子、慢慢擴散的光環。最容易出錯的是**精確的形狀與數量、文字、快速的爆發**，以及要和動作在某一格精確對上的東西（拳頭打中那一瞬間的衝擊）。文字與介面要能改、要精確，預設就交給後製；爆發照戲寫，工具定了、它做不好（`tool_limits.fast_motion` 是 `false`）再改。

### `desc` 怎麼寫

順序：形狀 → 顏色 → 光（發不發光、多亮）→ 質感與粒子 → 大小與範圍。寫成一個名詞短語，和道具一樣。

| 不好 | 好 |
|---|---|
| 強大的妖氣 | 一層貼著地面翻動的墨綠色薄霧，半透明，霧裡有細小的光點 |
| 催眠特效 | 一圈從指尖往外擴散的淡紫色光環，邊緣柔和，像水面的波紋 |
| 金光閃閃的印記 | 一枚淡金色的蓮花形印記，線條細，微微發光 |

- **一種能力一個顏色、一個形狀**，整季不變。角色和能力多的戲，先列一張特效色彩表，顏色不要撞。觀眾靠顏色分辨是誰的能力，生成工具也靠固定的描述畫出同一種東西。
- **發光的特效會照亮周圍**，寫在 `light`，用特效當主詞：「狐火在附近的臉和桌面上映出一層冷藍色的光」。腳本會把它接在那一鏡的光線後面，所以主詞不能省。畫面裡有一團光、臉上卻沒有反光，看起來就像貼上去的。
- **`detail` 寫只給參考圖看的細節**：粒子的大小與疏密、邊緣銳利還是柔散、內部的紋理與層次（「焰尖細碎地分岔，周圍飄著幾點米粒大的火星」）。`desc` 會進每一鏡，要短；`detail` 只進特效參考圖，可以寫細。
- **`motion` 寫怎麼動**：方向、速度、範圍怎麼變。「光環從指尖往外擴散，擴到肩膀寬就淡去」。爆發、炸開照實寫；選定的工具做不好快速的動作時，腳本會警告，那時再改成慢慢擴散、明暗起伏，或交給後製。

### 會變化的特效：`states`

印記一天比一天完整、香越燒越短、裂痕越來越長：每個階段寫成一個**完整的名詞短語**（連不變的部分一起寫），登記在 `states`：

```json
{
  "id": "F02",
  "name": "契約印",
  "desc": "一枚淡金色的蓮花形印記，線條細，微微發光",
  "states": {
    "花苞": "一枚淡金色的蓮花花苞形印記，花瓣合攏，線條細，微微發光",
    "半開": "一枚淡金色的半開蓮花形印記，三片花瓣張開，線條細，比花苞時亮",
    "全開": "一枚淡金色的全開蓮花形印記，八片花瓣完全展開，發出明顯的金光"
  },
  "motion": "印記的光緩慢地一明一暗，像呼吸",
  "light": "印記在掌心周圍映出一圈淡金色的光",
  "light_states": {
    "花苞": "印記在掌心映出一點微弱的淡金色光",
    "全開": "印記的金光照亮整個手掌與附近的臉"
  },
  "make": "生成"
}
```

- **每個階段的亮度不一樣，光也要跟著分階段。** `light` 只有一段時，每個狀態都會被寫成同樣照亮周圍，連還是一道淡痕的印記也一樣。在 `light_states` 寫各階段自己的光，沒列的狀態用 `light`；完全不發光的階段寫空字串 `""`，那一鏡就不加光。動態也一樣，用 `motion_states`（淡痕不會「一明一暗」）。有分狀態、`light` 卻只有一段時，腳本會提示。
- 鏡頭裡寫 `"fx": [{"id": "F02", "state": "花苞", "pos": "左手掌心正中"}]`。片段裡也可以寫 `{F02:半開}`，例如 `end`：「掌心的印記變成{F02:半開}」。
- 分集表的 `state` 用同一組名稱記錄每一集結束時到了哪一個階段，劇本和分鏡照著用，不會這一集寫「半開」、下一集寫「開了一半」。
- 道具也可以有 `states`（信拆了沒、燈亮不亮），用 `{P01:拆開}` 引用。只在一兩鏡出現的狀態，照舊寫在鏡頭裡就好。
- 腳本會替每個狀態出一張特效參考圖（純黑背景）。鏡頭的 `fx` 引用了那個特效（或那個狀態）時，腳本會自動把對應的參考圖列進這一鏡的參考圖清單，`refs` 不用再寫。

### 鏡頭裡怎麼用：`fx`

| 欄位 | 說明 |
|---|---|
| `id` | 特效編號 |
| `state` | 這一鏡是哪個狀態；沒有分狀態就不填 |
| `pos` | 片段。在畫面哪裡、附著在什麼上面：「浮在女子攤開的右手掌心上方」 |
| `motion` | 片段，可省略。這一鏡特效怎麼動，不填就用設定檔的 `motion_states` 或 `motion`；寫 `false` 表示這一鏡不加（已經寫在鏡頭的 `motion` 裡） |
| `light` | 片段，可省略。這一鏡特效怎麼照亮周圍，不填就用設定檔的 `light_states` 或 `light`；寫 `false` 表示這一鏡不加 |

腳本的組合：首幀提示詞在道具後面加上特效的樣子和位置，在光線後面加上特效的光；影片提示詞在鏡頭的 `motion` 後面加上特效怎麼動。

不要為了避開發光，把特效改登記成道具：道具沒有狀態的光與動態，參考圖模式下也不會指向特效參考圖。用 `light_states` 或這一鏡的 `light: false`。

### 後製的特效

`make` 是 `後製` 的特效不進提示詞。腳本會在那一鏡的備註寫「後製加特效」，並出一張設計圖給剪接的人參考。生成時要替它**留位置**：

- 會浮在畫面上的數字或字：`frame` 留一塊乾淨的空間（「掌心上方留一片暗色的空白」），不要寫「給後製的數字」：說出空白是給數字的，工具就會把數字畫上去，腳本會警告。
- 會附在身體上的：讓那個部位清楚入鏡、不被遮住（「左手掌心朝上攤開，正對鏡頭」）。
- 會照亮周圍的：光照樣寫進那一鏡的 `light`，後製再把特效疊上去，光才對得上。

`生成加後製` 的特效照樣進提示詞，備註會提醒後製加強。

### 法術對打與大場面

兩個角色用能力對打，拆法和打鬥一樣（`shot-craft.md` 第十節）：出手前的預兆一鏡（光在掌心聚起來）→ 相撞 → 結果一鏡（對手退了一步、桌上的東西被吹亂），每一下都看得出是誰佔上風。相撞的那一下照戲寫，在 `risk` 註明；選定的工具做不好時，改成閃白或反應鏡頭，相撞交給後製，或用聲音和旁人的反應帶過（`anti-ai-rules.md` 第六節）。

## 三、設定檔與交付

- 原文沒寫的顏色、大小、形狀、尾巴的數量，一樣先給一個具體的暫定值，列入 `pending`。
- 第一階段交付時，資產清單把異獸與原形的設定圖、每個特效的參考圖一起列出來。它們和角色設定圖一樣要先定稿，之後的鏡頭掛它們當參考圖。
