# 各生成工具的能力對照

**這份的限制在使用者選定工具之後才套用。** 動手前問參數時，只拿表裡的工具名稱當選項舉例；工具未定時，分鏡與提示詞照故事需要寫完整，不套用這裡的任何限制。定了工具，照這份填 `project` 的工具欄位與 `tool_limits`，重跑腳本，再照檢查結果適配（流程見 `storyboard-fix` 技能的「工具定了之後」，`../../storyboard-fix/SKILL.md`）。

> **查證日期：2026-11-25，2026-11-27 補查。** 每一列的第一格寫了那一列的狀態（正式版、預覽、哪一天下架）與查證日。內容以各家官方文件為主（來源列在最後）；只在第三方平台或新聞看到的，格子裡會寫明「第三方」。這個領域幾個月就會大改：這兩次查證就發現 Sora 已停止服務、Google 正在用 Gemini Omni 取代 Veo、好幾家換了大版本。
>
> 所以請這樣用這份表：
> - 使用者說的工具或版本不在表裡，或今天距離那一列的查證日超過三個月，而且你能上網搜尋：先查官方文件再決定參數。最後一節「下次要查的事」列了已知會變的日期，過了那一天就要重查。
> - 不能搜尋：照表填，並在交付時告訴使用者這些值可能過時，請他確認三件事：單次可生成幾秒、有沒有負面提示詞欄位、支不支援首尾幀。
> - 標「未查證」或「第三方」的格子不要當成事實。
> - **同一個模型在不同平台的限制不一樣**（免費和付費方案的秒數不同、某個平台不開放參考圖）。使用者說的是平台（Runway、即夢、Flow、各家漫劇平台），先問他在上面選的是哪一個模型，照那個模型的列填，再請他確認平台上的秒數與畫幅。

## 不太會變的做法

這幾條是各家文件共同的方向，比版本細節可靠。

- **先出首幀圖，再圖生影片。** 外貌和構圖在圖像階段鎖定，影片階段只管怎麼動。
- **圖生影片的提示詞只寫動作與運鏡。** Runway 的說法是「不要描述圖片裡已經有的東西，用提示詞描述畫面的運動」，Vidu 也是「專心描述動作，不要重複圖片內容」。腳本在圖生影片模式下就是這樣組合的。
- **正向描述比否定句穩。** 各家官方都提醒否定句容易適得其反（Runway：否定寫法可能產生相反的結果；可靈：負面提示會增加出錯機率；即夢：盡量使用正向描述；Veo：不要寫「不要」）。做法是把「不要什麼」改寫成「要什麼」：不寫「不要多餘手指」，而是在 `hands` 把兩隻手的位置寫清楚。目前多數影片工具沒有獨立的負面詞欄位：選定的工具沒有時，清空 `negative_global`，並在 `tool_limits` 填 `"negative": false`。可靈與即夢的文件提到「不要字幕」「無背景音樂」這類短指令是有效的，寫在 `audio_suffix`；Gemini Omni 的文件也說可以在提示詞裡寫「Do not …」，但正向描述仍然是首選。
- **台詞用雙引號括起來。** 有原生音訊的工具都用引號辨識台詞，腳本在「原生音訊」方案下會自動這樣寫。提示詞是英文、台詞是中文時，填 `speech_lang` 讓腳本註明用哪種語言說。不想要工具自己加字幕，把「不要字幕」填進 `audio_suffix`。
- **參考圖用工具自己的指稱語法**（例如 `@Image1`、`@图片1`），把 `refs` 欄列的圖依序掛上去。
- **一鏡一段。** 好幾個工具會自己把一段影片切成幾個鏡頭（可靈的多鏡頭預設開啟，Gemini Omni 不特別要求時也會切）。這份分鏡是一鏡一段生成：關掉多鏡頭，或在 `video_suffix` 寫「單一連續鏡頭」（英文 a single continuous shot, no scene cuts）。

### 填 `tool_limits`

`tool_limits` 記的是**這個工具確定做不好的事**，填 `false` 的項目腳本才會檢查，分鏡也才會照它換拍法：

| 項目 | 填 `false` 的時候 | 腳本會檢查什麼 |
|---|---|---|
| `text` | 工具寫不好畫面裡的字 | 片段要求畫面出現可讀文字、寫到「數字」「文字」、特效包含文字 |
| `fast_motion` | 工具做不好快速、劇烈的動作（打鬥、撲、摔、爆發） | `motion` 與特效動態裡的「快速、劇烈、瞬間、爆發」這類字眼 |
| `complex_camera` | 工具做不穩甩鏡、環繞、滑動變焦 | 用了這些運鏡卻沒寫 `risk` 備案 |
| `negative` | 工具沒有獨立的負面詞欄位 | `negative_global` 或鏡頭的 `negative` 還有內容 |

- 只填查得到、或測過的。官方文件明寫、上表有寫的，照填；表裡沒有、寫「未查證」或「第三方」的，先不填。
- 沒把握的項目用測試決定：照分鏡挑一兩鏡最難的（一個打鬥的出手、一個有字的招牌、一個環繞），各生成兩三次。同樣的錯出現兩次以上，那一項填 `false`，重跑腳本，照 `anti-ai-rules.md` 第六節換拍法。
- 圖像工具和影片工具都算：字是在首幀圖裡寫的，看圖像工具；動作與運鏡看影片工具。
- 換工具時整組重填，不要沿用上一個工具的。

### 秒數與裁頭尾

- 生成的片段頭尾常常有一點變形或停頓。腳本以頭尾共裁 1 秒算「建議生成秒數」：成片 3 秒的鏡頭建議生成 4 秒，而且不小於工具最短的長度。成片秒數加 1 秒超過工具上限時，腳本會警告，那一鏡要拆。
- 鏡頭比工具最短的片段還短時，照樣生成最短的那一段，剪的時候取動作最好的部分。這種鏡頭的動作要短到在保留的那一段裡做得完（踏出一步、刀光一閃），否則剪接時得變速，在 `post` 註明。
- 工具能一次生成很長的片段，不代表分鏡要寫長鏡頭。單鏡的長度仍照形式與內容決定（novel-to-storyboard 的 `SKILL.md` 第五步最後的表），長片段留給真的需要連續表演的鏡頭；一段越長，中途走樣的機會越大。

### 參考圖模式的設定

`ref_mode` 作用在首幀，所以看的是**圖像工具**；`video_mode` 是 `t2v` 時才看影片工具。指稱語法是查證時官方文件寫的寫法，介面版本可能不同，第一次用先生成一兩鏡確認編號有被認出來。`ref_max` 填的是**參考圖的張數**：工具的上限是「素材總數」（圖、影片、元素加起來）時，填其中圖的上限。

**Midjourney 的參數寫在提示詞裡。** 畫幅（`--ar 9:16`）、負面詞（`--no text, watermark`）、風格參考（`--sref`）都接在提示詞最後，不是介面上的選項。填進 `project.image_suffix`（首幀、尾幀、機位背景圖用）與 `project.asset_suffix`（角色設定圖、頭像、道具圖這類資產用），兩個都寫成 `"--ar {ar} --v 8"` 這樣：腳本會把 `{ar}` 換成那一張圖的畫幅（鏡頭照影片，資產照各自的建議畫幅），再接在提示詞的最後；`negative_global` 是給有獨立負面詞欄位的工具用的，不要把 Midjourney 的 `--no` 寫在那裡。參考圖用 Edit Model 掛，`ref_mode` 用 `文字`。版本參數（`--v`）照使用者實際用的版本填，這裡沒有查證預設值；V9 推出後要重查參考圖的掛法。

**長度上限要分清楚是上限還是建議。** 工具寫明的硬上限（例如可靈 4.0 的 8,000 token）才填進 `prompt_limits`，腳本會檢查每一鏡組合後的提示詞有沒有超過，超過就警告。官方只是「建議」的長度（例如即夢圖像的 300 字）不要填：腳本會把它當成上限，對每一鏡較長的提示詞都發警告。真的覺得提示詞太長，照 `prompt-writing.md` 第六節縮：填 `bg`、`outfit_top`，把背影角色設成 `partial`，或改用參考圖模式。工具未定時不填，提示詞不受長度限制。

真人寫實（`medium: 真人寫實`）的工具選擇：先確認圖像工具出的是照片質感、不是插畫或 3D 渲染，再確認它和影片工具能不能接受真人的臉當參考圖（有些工具會擋寫實人臉的上傳或生成）。這兩件事都沒有逐一查證，第一張定妝照就是測試。

## 各工具官方的提示詞寫法

查證日期 2026-11-25，2026-11-27 補查 Google 的部分。這裡只記官方頁面寫到的；片段的通用寫法見 `prompt-writing.md`。

| 工具 | 官方指南怎麼說 | 對這個 skill 的影響 |
|---|---|---|
| 可靈 4.0 | 用描述性的語言，少用抽象詞與否定指令；真正需要的否定只有「不要字幕」「不要背景音樂」。台詞用敘述帶出、放在引號裡，語氣由敘述的動詞表達（…shouts: "…"）。運鏡寫成自然的句子，範例用到 push-in、pull-out、pan、tracking shot、orbit shot、handheld。多鏡頭功能預設開啟，模型會自己把一段影片切成幾個鏡頭，指南沒有寫怎麼關 | 片段照通則寫。這份分鏡是一鏡一段：生成時關掉多鏡頭，或在 `video_suffix` 寫「單一連續鏡頭」（這一句的效果沒有實測） |
| 即夢 Seedance 2.5 | 以下取自頁面後段的摘要，不是逐字讀到，引用前請複核。建議的結構是：各個素材的用途 → 一句總述 → 依時間或鏡頭順序寫細節。台詞格式是「某某說："…"」，情緒寫在說話者後面的括號裡。運鏡用詞有推、拉、搖、移、跟、環繞、手持晃動、固定鏡頭；景別用詞有大全景、全景、中景、近景、特寫 | 腳本輸出的中文景別與運鏡用詞和它一致 |
| Google Veo 3.1 | 把想法拆成要素：主體、動作、場景、鏡頭角度、運鏡、鏡頭與光學效果、視覺風格、時間要素、聲音；不必每一項都寫。不要寫 no、don't，改用描述。聲音用獨立的句子寫。這份指南的台詞範例是 The detective says: …，沒有加引號；語氣用描述帶出（in a serious, urgent tone）。圖生影片要給具體的動作描述：運鏡、主體動作、環境效果 | 腳本的英文運鏡用詞（pan、tilt、truck、pedestal、zoom、arc shot）取自這份指南。腳本的台詞一律加引號，和上面「不太會變的做法」一致 |
| Google Gemini Omni | 有自己的指南與 API 文件，和 Veo 的不同：否定可以寫成「Do not …」放在提示詞裡；台詞範例用雙引號；不特別要求時，模型常把一段切成好幾個鏡頭，要一鏡到底就寫 a single continuous shot 或 no scene cuts；參考圖用文字描述是哪一張，不用編號 | 一鏡一段：在 `video_suffix` 寫 a single continuous shot, no scene cuts。參考圖用文字模式（見上面的參考圖表） |
| FLUX 3 | 沒有負面詞欄位。把否定換成正面的詞：no people 改成 empty、deserted。圖像編輯可以直接下指令（Remove the cat from the sofa） | 空鏡的英文寫法用 scenery only, unoccupied；尾幀與造型變體的編輯指令適用 |
| 即夢圖像 Seedream | API 文件只有長度建議（中文 300 字、英文 600 詞），寫的是「建議」。另有一份提示詞指南，這次沒有讀 | 長度建議不要填進 `prompt_limits`（見上一節） |
| Midjourney、Runway | 官方說明頁擋了自動讀取，這次沒有查到提示詞寫法 | 使用者用這兩個工具時，建議先生成一兩鏡，對照官方的提示詞指南調整後再大量生成 |

## 聲音與後製

這部分沒有逐一查證版本，只列分工：

- **口型**：工具的原生音訊做不到，或聲線每鏡不一致時，用獨立的對口型工具處理，對白鏡頭保持固定機位。
- **配音與旁白**：TTS 或真人錄音，每個角色先固定聲線。可靈 4.0、Vidu Q4 可以掛聲音參考，讓同一個角色每鏡的聲音一致。
- **剪接、調色、字幕、混音**：剪映、CapCut、DaVinci Resolve 這類剪輯軟體。
