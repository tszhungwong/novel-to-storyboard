# 各生成工具的能力對照

**這份在使用者選定工具之後才用。** 工具未定時，分鏡與提示詞照故事需要寫完整，不套用這裡的任何限制；定了工具，照這份填 `project` 的工具欄位與 `tool_limits`，重跑腳本，再照檢查結果適配（流程見 `SKILL.md` 的「工具定了之後」）。

> **查證日期：2026-11-25。** 內容來自各家官方文件（來源列在最後）。這個領域幾個月就會大改，這次查證時就發現 Sora 已停止服務、可靈與即夢都換了大版本、Google 正在用 Gemini Omni 取代 Veo。
>
> 所以請這樣用這份表：
> - 使用者說的工具或版本不在表裡，或今天距離查證日期超過三個月，而且你能上網搜尋：先查官方文件再決定參數。
> - 不能搜尋：照表填，並在交付時告訴使用者這些值可能過時，請他確認三件事：單次可生成幾秒、有沒有負面提示詞欄位、支不支援首尾幀。
> - 標「未查證」的格子不要當成事實。

## 不太會變的做法

這幾條是各家文件共同的方向，比版本細節可靠。

- **先出首幀圖，再圖生影片。** 外貌和構圖在圖像階段鎖定，影片階段只管怎麼動。
- **圖生影片的提示詞只寫動作與運鏡。** Runway 的說法是「不要描述圖片裡已經有的東西，用提示詞描述畫面的運動」，Vidu 也是「專心描述動作，不要重複圖片內容」。腳本在圖生影片模式下就是這樣組合的。
- **正向描述比否定句穩。** 各家官方都提醒否定句容易適得其反（Runway：否定寫法可能產生相反的結果；可靈：負面提示會增加出錯機率；即夢：盡量使用正向描述；Veo：不要寫「不要」）。做法是把「不要什麼」改寫成「要什麼」：不寫「不要多餘手指」，而是在 `hands` 把兩隻手的位置寫清楚。目前多數影片工具沒有獨立的負面詞欄位：選定的工具沒有時，清空 `negative_global`，並在 `tool_limits` 填 `"negative": false`。可靈與即夢的文件提到「不要字幕」「無背景音樂」這類短指令是有效的，寫在 `audio_suffix`。
- **台詞用雙引號括起來。** 有原生音訊的工具都用引號辨識台詞，腳本在「原生音訊」方案下會自動這樣寫。提示詞是英文、台詞是中文時，填 `speech_lang` 讓腳本註明用哪種語言說。不想要工具自己加字幕，把「不要字幕」填進 `audio_suffix`。
- **參考圖用工具自己的指稱語法**（例如 `@Image1`、`@图片1`），把 `refs` 欄列的圖依序掛上去。

### 填 `tool_limits`

`tool_limits` 記的是**這個工具確定做不好的事**，填 `false` 的項目腳本才會檢查，分鏡也才會照它換拍法：

| 項目 | 填 `false` 的時候 | 腳本會檢查什麼 |
|---|---|---|
| `text` | 工具寫不好畫面裡的字 | 片段要求畫面出現可讀文字、寫到「數字」「文字」、特效包含文字 |
| `fast_motion` | 工具做不好快速、劇烈的動作（打鬥、撲、摔、爆發） | `motion` 與特效動態裡的「快速、劇烈、瞬間、爆發」這類字眼 |
| `complex_camera` | 工具做不穩甩鏡、環繞、滑動變焦 | 用了這些運鏡卻沒寫 `risk` 備案 |
| `negative` | 工具沒有獨立的負面詞欄位 | `negative_global` 或鏡頭的 `negative` 還有內容 |

- 只填查得到、或測過的。官方文件明寫、上表有寫的，照填；表裡沒有、寫「未查證」的，先不填。
- 沒把握的項目用測試決定：照分鏡挑一兩鏡最難的（一個打鬥的出手、一個有字的招牌、一個環繞），各生成兩三次。同樣的錯出現兩次以上，那一項填 `false`，重跑腳本，照 `anti-ai-rules.md` 第六節換拍法。
- 圖像工具和影片工具都算：字是在首幀圖裡寫的，看圖像工具；動作與運鏡看影片工具。
- 換工具時整組重填，不要沿用上一個工具的。

### 秒數與裁頭尾

- 生成的片段頭尾常常有一點變形或停頓。腳本以頭尾共裁 1 秒算「建議生成秒數」：成片 3 秒的鏡頭建議生成 4 秒，而且不小於工具最短的長度。成片秒數加 1 秒超過工具上限時，腳本會警告，那一鏡要拆。
- 鏡頭比工具最短的片段還短時，照樣生成最短的那一段，剪的時候取動作最好的部分。這種鏡頭的動作要短到在保留的那一段裡做得完（踏出一步、刀光一閃），否則剪接時得變速，在 `post` 註明。
- 工具能一次生成很長的片段，不代表分鏡要寫長鏡頭。單鏡的長度仍照形式與內容決定（`SKILL.md` 第五步的表），長片段留給真的需要連續表演的鏡頭；一段越長，中途走樣的機會越大。

### 參考圖模式的設定

`ref_mode` 作用在首幀，所以看的是**圖像工具**；`video_mode` 是 `t2v` 時才看影片工具。指稱語法是查證時官方文件寫的寫法，介面版本可能不同，第一次用先生成一兩鏡確認編號有被認出來。

| 工具 | `ref_mode` | `ref_syntax` | `ref_max` |
|---|---|---|---|
| 即夢圖像 Seedream 5.5 | `參考圖` | 未查證；先用 `"圖{n}"`，不認得再改 | `10` |
| FLUX 3 | `參考圖` | `"image {n}"` | `10` |
| Midjourney V8.2 | `文字` | 參考圖由 Edit Model 掛，提示詞裡沒有編號語法 | — |
| 可靈 4.0（全能參考，`t2v` 時） | `參考圖` | `"@Image{n}"` | `15` |
| 即夢 Seedance 2.5（全能參考，`t2v` 時） | `參考圖` | `"@图片{n}"` | `30` |
| Veo 3.1（素材生影片，`t2v` 時） | `文字` | 未查到編號語法 | 3 |
| 表裡沒有的工具 | `文字` | | |

可靈 4.0 的文件說它能穩定生成畫面中的文字。短的字（招牌上的兩三個字）照寫，在 `risk` 註明要檢查字有沒有寫對；長的文字（訊息、信件）仍然建議後製加，好改也好讀。

| 工具（查證時的版本） | 提示詞語言 | 負面詞 | 參考圖 | 長度上限 |
|---|---|---|---|---|
| **即夢圖像 Seedream 5.5**（2026-11 發布） | 中文、英文都支援 | API 沒有這個參數；即夢介面未查證 | 最多 10 張 | 約 300 個中文字或 600 個英文詞 |
| **Midjourney V8.2**（2026-07 起為預設） | 官方範例是英文；未查到明文說明 | `--no 項目, 項目` | V8.1 與 V8.2 用 Edit Model 掛最多 4 張參考圖，取代了 `--oref` 與 `--cref`；`--sref` 風格參考仍可用。`--oref` 只適用 V7，`--cref` 是更舊的參數 | 未查證 |
| **FLUX 3**（2026-10 發布） | 官方範例是英文；中文提示詞未查證 | 沒有負面詞欄位（`"negative": false`） | 最多 10 張，在提示詞裡用 image 1、image 2 指稱 | 未查證 |

**Midjourney 的參數寫在提示詞裡。** 畫幅（`--ar 9:16`）、負面詞（`--no text, watermark`）、風格參考（`--sref`）都接在提示詞最後，不是介面上的選項。填進 `project.image_suffix`（首幀、尾幀、機位背景圖用）與 `project.asset_suffix`（角色設定圖、頭像、道具圖這類資產用），兩個都寫成 `"--ar {ar} --v 8"` 這樣：腳本會把 `{ar}` 換成那一張圖的畫幅（鏡頭照影片，資產照各自的建議畫幅），再接在提示詞的最後；`negative_global` 是給有獨立負面詞欄位的工具用的，不要把 Midjourney 的 `--no` 寫在那裡。參考圖用 Edit Model 掛，`ref_mode` 用 `文字`。版本參數（`--v`）照使用者實際用的版本填，這裡沒有查證預設值。

表裡沒有的圖像工具（例如 Google 的圖像模型、可靈自己的圖像生成）這次沒有查證，使用者用到時請他確認長度上限與參考圖張數，或上網查。

圖像工具有長度上限時，填進 `prompt_limits`，腳本會檢查每一鏡組合後的提示詞有沒有超過，例如即夢圖像：`"prompt_limits": {"image": {"zh": 300, "en": 600}}`。兩個角色都完整描述的鏡頭很容易超過，解法照 `prompt-writing.md` 第六節：填 `bg`、`outfit_top`，把背影角色設成 `partial`，或改用參考圖模式。工具未定時不填，提示詞不受長度限制。

真人寫實（`medium: 真人寫實`）的工具選擇：先確認圖像工具出的是照片質感、不是插畫或 3D 渲染，再確認它和影片工具能不能接受真人的臉當參考圖（有些工具會擋寫實人臉的上傳或生成）。這兩件事這次都沒有逐一查證，第一張定妝照就是測試。

## 各工具官方的提示詞寫法

查證日期 2026-11-25。這裡只記官方頁面寫到的；片段的通用寫法見 `prompt-writing.md`。

| 工具 | 官方指南怎麼說 | 對這個 skill 的影響 |
|---|---|---|
| 可靈 4.0 | 用描述性的語言，少用抽象詞與否定指令；真正需要的否定只有「不要字幕」「不要背景音樂」。台詞用敘述帶出、放在引號裡，語氣由敘述的動詞表達（…shouts: "…"）。運鏡寫成自然的句子，範例用到 push-in、pull-out、pan、tracking shot、orbit shot、handheld。多鏡頭功能預設開啟，模型會自己把一段影片切成幾個鏡頭 | 片段照通則寫。這份分鏡是一鏡一段：生成時關掉多鏡頭，或在 `video_suffix` 寫「單一連續鏡頭」（這一句的效果沒有實測） |
| 即夢 Seedance 2.5 | 以下取自頁面後段的摘要，不是逐字讀到，引用前請複核。建議的結構是：各個素材的用途 → 一句總述 → 依時間或鏡頭順序寫細節。台詞格式是「某某說："…"」，情緒寫在說話者後面的括號裡。運鏡用詞有推、拉、搖、移、跟、環繞、手持晃動、固定鏡頭；景別用詞有大全景、全景、中景、近景、特寫 | 腳本輸出的中文景別與運鏡用詞和它一致 |
| Google（Gemini Omni Flash 與 Veo 共用一份指南） | 把想法拆成要素：主體、動作、場景、鏡頭角度、運鏡、鏡頭與光學效果、視覺風格、時間要素、聲音；不必每一項都寫。不要寫 no、don't，改用描述。聲音用獨立的句子寫。這份指南的台詞範例是 The detective says: …，沒有加引號；語氣用描述帶出（in a serious, urgent tone）。圖生影片要給具體的動作描述：運鏡、主體動作、環境效果 | 腳本的英文運鏡用詞（pan、tilt、truck、pedestal、zoom、arc shot）取自這份指南。腳本的台詞一律加引號，和上面「不太會變的做法」一致 |
| FLUX 3 | 沒有負面詞欄位。把否定換成正面的詞：no people 改成 empty、deserted。圖像編輯可以直接下指令（Remove the cat from the sofa） | 空鏡的英文寫法用 scenery only, unoccupied；尾幀與造型變體的編輯指令適用 |
| 即夢圖像 Seedream | API 文件只有長度建議（中文 300 字、英文 600 詞）。另有一份提示詞指南，這次沒有讀 | 無 |
| Midjourney、Runway | 官方說明頁擋了自動讀取，這次沒有查到提示詞寫法 | 使用者用這兩個工具時，建議先生成一兩鏡，對照官方的提示詞指南調整後再大量生成 |

## 聲音與後製

這部分沒有逐一查證版本，只列分工：

- **口型**：工具的原生音訊做不到，或聲線每鏡不一致時，用獨立的對口型工具處理，對白鏡頭保持固定機位。
- **配音與旁白**：TTS 或真人錄音，每個角色先固定聲線。
- **剪接、調色、字幕、混音**：剪映、CapCut、DaVinci Resolve 這類剪輯軟體。
