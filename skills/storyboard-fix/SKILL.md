# 分鏡做好之後：換工具、修改、生成結果不對

這個技能處理分鏡做好之後的三件事：工具定了之後的適配、修改既有分鏡、生成結果不對時怎麼改。三件事的原則一樣：**改設定檔或分鏡檔的欄位，再重跑腳本。** 不要只改組合好的提示詞，也不要改 CSV 裡的提示詞欄位，下次重跑都會被蓋掉。

回覆語言跟隨使用者，預設繁體中文。

**檔案在哪裡。** 這個技能和 `novel-to-storyboard` 裝在同一個 plugin 裡，共用它的腳本與參考文件。下面寫的 `../novel-to-storyboard/` 是相對於這個技能資料夾的路徑：

- 腳本：`../novel-to-storyboard/scripts/build_storyboard.mjs`
- 欄位定義：`../novel-to-storyboard/references/fields.md`
- 各工具的能力與怎麼填工具欄位：`../novel-to-storyboard/references/tool-capabilities.md`
- 驗收標準、症狀與改法：`../novel-to-storyboard/references/generation-qa.md`
- 片段的寫法：`../novel-to-storyboard/references/prompt-writing.md`
- 換拍法：`../novel-to-storyboard/references/anti-ai-rules.md` 第二部分

## 先讀現況

1. 找到專案的 `storyboard/bible.json`（含 `project` 的工具欄位、`pending`、`log`）和要改的那幾集 `EPxx.json`。找不到就問使用者放在哪裡；使用者只貼了提示詞、沒有分鏡檔時，照 `generation-qa.md` 給改法，並說明有分鏡檔才能一起改、重跑。
2. 先跑一次腳本，看現在的檢查結果，改完才分得出哪些是新出現的問題：

```bash
node <這個技能的資料夾>/../novel-to-storyboard/scripts/build_storyboard.mjs storyboard/bible.json storyboard/EP01.json
```

3. 參數不重問。形式、媒材、聲音方案都在 `project` 裡；這次要改的正是其中一項時，才照使用者說的改。

## 工具定了之後

使用者選定（或換了）圖像、影片工具時，做一次適配。設定檔的外貌、場景、風格和分鏡的走位都不用動，改的是工具欄位和少數鏡頭的拍法：

1. 查 `tool-capabilities.md`。使用者說的工具或版本不在表裡，或今天距離表上的查證日期超過三個月，而且能上網搜尋：先查那個工具的官方文件。然後照表裡的「怎麼填」填 `project` 的工具欄位：`image_tool`、`video_tool`、`prompt_langs`、`use_last_frame`、`clip_range` 或 `clip_lengths`、`prompt_limits`、`ref_mode` 與 `ref_syntax`、`ref_max`、`video_mode`（全能參考這類只吃文字加參考圖的模式填 `t2v`）、`speech_lang`（原生音訊時台詞語言和提示詞語言不同才填）、要接在提示詞最後的 `image_suffix`、`asset_suffix`（Midjourney 這類把參數寫在提示詞裡的工具）、`video_suffix`、`audio_suffix`，以及 `tool_limits`（這個工具做不好的事）。工具沒有負面詞欄位就清空 `negative_global`。查不到、或表裡寫「未查證」的項目先不填，請使用者生成一兩鏡測試，做壞了再補上；不能上網時照表填，交付時請使用者確認三件事：單次可生成幾秒、有沒有負面詞欄位、支不支援首尾幀。
2. 每一集重跑腳本，照檢查結果修：超過單次秒數的拆鏡；提示詞超過長度上限的照 `prompt-writing.md` 第六節縮；參考圖超過張數的減少引用。
3. `tool_limits` 裡是 `false` 的項目，照 `anti-ai-rules.md` 第二部分換拍法：快速動作拆成預備、結果與反應；字改成後製；甩鏡改成轉場、環繞改成推近。`risk` 寫了備案的鏡頭，先看備案是不是就是答案。
4. 提示詞語言變了（中文改英文），片段要重寫成新語言，不是逐字翻譯，見 `prompt-writing.md` 第五節。
5. 交付時列出改了哪些鏡頭、為什麼改。

工具能在一段生成裡切好幾個鏡頭時（多鏡頭、時間碼提示詞），分鏡仍然一鏡一筆；使用者想把同一場戲相鄰的幾鏡合成一段生成，再照該工具的指南合併那幾鏡的提示詞。

## 修改既有分鏡

- **改角色、場景、道具或風格**：改 `bible.json`，把每一集重跑一次。已經定稿的資產圖受影響時，提醒使用者重新生成那張資產圖，以及用到它的鏡頭。
  - 已有的描述只改使用者要改的那一處，其餘一個字都不要動：改寫舊描述，前後集的角色會長得不一樣。
  - 只是某一集起換裝、受傷、變髒：新開一個造型變體，從那一集起引用它，不要改原本的造型。
- **改某幾鏡**：改對應的 `EPxx.json` 後重跑。插入鏡頭時用 `EP01-004a` 這種鏡號，不要重編後面的號碼：使用者可能已經用舊鏡號生成了素材，CSV 的手填紀錄也是按鏡號對回去的。刪掉的鏡頭，紀錄會移到 `EPxx-shots-已移除.csv`。
- **改動牽動前後鏡**：改了一鏡的走位、道具或光線，看前一鏡的 `end` 和後一鏡的開頭還接不接得上；改了節拍或高點，看 `plan` 要不要跟著改。拆鏡的方法見 `../novel-to-storyboard/references/shot-craft.md`。
- **改動多到等於重拆一場戲**：照 `novel-to-storyboard` 的第五到第七步重做那一場，包含三個角色的審查。

## 生成結果不對

1. **先弄清楚是哪一鏡、哪個階段、什麼症狀**：資產圖、首幀、尾幀還是影片；使用者貼了圖就看圖。說不清楚時問一句，不要猜著改。
2. **照 `generation-qa.md` 第二節的症狀表找原因**，先看那一鏡在分鏡表裡的「驗收重點」。原因常常在上游：資產圖沒定稿、參考圖掛錯張、首幀就已經錯了。上游錯的先修上游，再往下重做。
3. **改欄位、重跑，只重新生成受影響的部分。** 改了資產圖，用到它的鏡頭都要重出首幀；只改了 `motion`，首幀可以留著，只重跑影片。改提示詞的原則見 `generation-qa.md` 第三節：一次改一件事，才知道是哪一處有效。
4. **同一種錯誤反覆出現，多半是工具做不到**：在 `tool_limits` 記下來，整集一起換拍法（見上一節第 3 點）。
5. 提醒使用者在 CSV 的「驗收結果」「備註」記下這次的結果。重跑腳本不會清掉這些手填欄位。

## 交付

1. 改了哪些欄位、為什麼改，以及對原文或劇情有沒有影響。
2. 要重新生成的清單，分開列：資產圖、首幀、尾幀、影片，各自是哪幾鏡。沒受影響的不用重做，也說一句。
3. 重跑後的檢查結果：錯誤與警告修完了沒有，保留未修的說明原因。
4. 改了設定（外貌、場景、風格）時，`pending` 裡對應的那一條和分集表裡的描述也一起改了。
